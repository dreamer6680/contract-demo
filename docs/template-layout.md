# 原版煤炭买卖合同模板：布局基线

> 本文档根据原版 DOCX 的结构拆解整理，作为模板维护、生成逻辑和回归检查的基线。实际生成仍以仓库中的原始 DOCX 文件为准；本文件不是替代模板的样式配置。

## 1. 页面与分节（`word/document.xml` 的 `w:sectPr`）

| 属性 | 基线值 | 说明 |
|---|---:|---|
| 页面宽度 | 11906 twips | A4 横向尺寸参数之一 |
| 页面高度 | 16838 twips | A4 |
| 上边距 | 1608 twips | 约 2.84 cm |
| 右边距 | 852 twips | 约 1.50 cm |
| 下边距 | 1080 twips | 约 1.90 cm |
| 左边距 | 1136 twips | 约 2.00 cm |
| 页眉距边界 | 720 twips | 约 1.27 cm |
| 页脚距边界 | 720 twips | 约 1.27 cm |
| 分栏 | 单栏，space=720 | 不应在生成时重建分节 |

v1 与 v2 的已知差异：v1 下边距为 2160 twips（约 3.81 cm），v2 为 1080 twips（约 1.90 cm）；其余已知页面参数、字体和字号分布一致。当前项目应以实际使用的 v2 模板为基准。

## 2. 页眉、页脚

- 模板只有 `footer1.xml`，没有页眉。
- 页脚右对齐，包含 `PAGE \\* MERGEFORMAT` 页码域，字号 9 pt。
- 生成时应保留原页脚 XML 和页码域，不要用普通文本替换页码域。

## 3. 样式表与直接格式

### 全局默认

- 西文字体：Times New Roman。
- 中文字体：宋体。
- 语言：`en-US / zh-CN`。
- 样式表较薄，正文多数依赖段落/运行级直接格式。

### 主要段落样式

| 样式 ID | 用途 | 基线格式 |
|---|---|---|
| `1` | Heading 1 | 宋体，18 pt，居中，右缩进 278 twips |
| `2` | Heading 2 | 楷体，14 pt，居中 |
| `a` | Normal | 宋体，12 pt，left=20、right=3257、hanging=10 twips |
| `footer` / `header` | 页眉页脚样式 | 基于 Normal，9 pt |
| `TableGrid` | 表格 | 细边框 |

> 重要：不要只改 `styles.xml` 来尝试改变正文排版。正文大量格式写在 `w:pPr` 和 `w:rPr` 中。编辑段落时需要保留这些属性；插入新段落时应从语义和格式对应的锚点段落复制属性。

## 4. 字体与字号

| 字体 | 字号 | 已知用途 |
|---|---:|---|
| 微软雅黑 | 22 pt，粗体 | 封面标题“煤炭买卖合同” |
| 微软雅黑 | 16 pt / 15 pt | 大标题、栏目标题 |
| 楷体 | 14 pt | 条款正文中的部分段落 |
| 继承默认字体 | 15 pt | 条款正文主体 |
| 继承默认字体 | 10.5 pt / 9 pt | 表格文字、页脚等 |
| 仿宋 | 10.5 pt | 个别段落 |

已知字号分布以半点值记录：44→22 pt、32→16 pt、30→15 pt、28→14 pt、24→12 pt、21→10.5 pt、18→9 pt。

## 5. 段落格式

- 已知对齐分布：居中 9 段、两端对齐 7 段、右对齐 1 段（签字栏）。
- 常见行距：`line=360, lineRule=auto`（约 1.5 倍）；另有 `line=368`（约 1.53 倍）。
- 多数段落 `after=0`；部分段落使用 `after=141/160/400`。
- 已知缩进值包括 `right=0`、`left/right/firstLine=0`、`left=475`、`left=115`、`right=2457`（签字栏）、`hanging=420`。
- 修改时保留原段落的 `w:pPr`；不要用 CSS 或手工空格模拟 Word 缩进。

## 6. 编号规则

模板使用 10 组 `numId`：

- `numId=3..10`：章节使用十进制三级编号，格式依次类似 `1.`、`1.1.`、`1.1.1.`，各章节独立计数。
- `numId=1`：合同填写说明，格式为 `1、`，子层级为 lowerLetter、lowerRoman。
- `numId=2`：违约责任/免责条款子项，包含 `%1.`、`(%2)`、带圈数字等格式。

不要把编号直接拼进正文字符串代替 Word 编号属性；应保留原有 `w:numPr` 与编号定义。

## 7. 表格

### 标的物表（4 行）

包含资源方、品种、品质规格、合同总量等字段，对应业务占位符包括：

- `{<$.seller.name>}`
- `{<$.product.type>}`
- `{<$.product.specs>}`
- `{<$.product.quantity>}`
- 合计含税金额大写：`{<$.product.priceInChinese>}`

### 签字盖章表

左右两栏分别对应甲方和乙方，包含“法定代表人（委托代理人）签字（章）”及签署日期 `{<$.signDate>}`。

原 DOCX 中未绘制签章框。电子签章位置由业务系统的 `ContractTask` 坐标配置处理（已知示例：`createPersonSignField(6, 520L, 750L)`，骑缝章坐标 `400L/800L`）；它属于另一套配置，不应混入 DOCX 样式逻辑。

## 8. 修改和生成时的约束

1. 原始 DOCX 是唯一版式来源，不在前端重新制作一份“看起来相似”的合同。
2. 业务字段只由后端提供；按原占位符进行替换，不要求用户编辑占位符。
3. 固定条款的修改只作用于当前生成副本，不覆盖公共模板。
4. 替换文本时优先保留目标段落的 `w:pPr` 和首个 run 的 `w:rPr`；若一段内有多种字符格式，应尽量按原 runs 分段替换，不应无条件合并为一个 run。
5. 新增段落需复制语义对应的锚点段落属性，包括段落格式、编号属性和 run 字体格式；若要跨多段落编辑，优先一一对应更新原段落。
6. 生成 DOCX 后转换成 PDF，并以实际 PDF 检查分页、字体、表格和签字位置。
7. 任何对模板的更新都应与这份基线比较；基线中的具体值应以仓库当前 DOCX 实际解析结果为准。

## 9. 建议的回归检查

- [ ] A4 页面尺寸与四边距符合当前 v2 模板。
- [ ] 页脚页码域仍可自动更新。
- [ ] 标的物表格与签字盖章表仍存在，行列结构不变。
- [ ] 占位符均被替换，生成文件中无残留 `{<$. ...>}`。
- [ ] 各章节编号、子项编号仍由 Word 编号定义驱动。
- [ ] 条款正文的字体、字号、行距、缩进与原段落一致。
- [ ] 多行条款和新增条款不会意外破坏页边距、表格或签字区。
- [ ] PDF 与原版模板在未编辑条款时尽可能保持一致。
